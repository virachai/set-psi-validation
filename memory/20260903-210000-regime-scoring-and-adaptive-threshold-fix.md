description: Fixed two logic bugs found during code review — Unclassified counted as a correct match, and the volatility threshold being a hardcoded constant despite being documented and labeled as a 30-day rolling figure.
type: feedback

**Bug 1 — Unclassified scored as correct.** `regime_rules.compare_regimes()` used plain string equality, so `compare_regimes("Unclassified", "Unclassified")` returned `True` (locked in by a test assertion). Because `predictedRegime` defaults to `"Unclassified"` when the PSI Engine API doesn't return a recognizable regime, and `actualRegime` becomes `"Unclassified"` whenever a trading day doesn't fit any defined bucket, a day where both sides failed to classify was recorded as `isCorrect: true` — silently inflating accuracy in `reports/metrics.json`. Fixed by making `compare_regimes()` return `False` whenever either side is `"Unclassified"`, and `compute_deviation_score()` now derives from `compare_regimes()` instead of its own separate equality check, so the two can no longer drift apart. Updated both `tests/python/test_regime_rules.py` and `tests/python/test_validation_engine.py`, which had duplicate assertions of the old (wrong) behavior in two places.

**Bug 2 — volatility threshold not actually adaptive.** `docs/02_research_reports/001-actual-regime-derivation-logic-v01.md` documents `Threshold_Mean` as something that "must be calculated daily based on a 30-day rolling window of historical volatility," and `capture_market.py`'s `--threshold` CLI flag was even labeled "30-day rolling volatility threshold mean" — but the value was a hardcoded `0.02` constant everywhere it was used (`DEFAULT_THRESHOLD_MEAN` in `regime_rules.py`, the flag's default). Added `compute_rolling_threshold_mean(date_str, window_days=30)` to `capture_market.py`: it reads `volatilityIndex` from prior days' completed `market-data/*-atc.json` files (excluding the current/future date to avoid lookahead), averages the trailing 30, and falls back to the static `0.02` default when fewer than 5 prior days exist (cold start). `--threshold` now defaults to `None` so an explicit CLI value still overrides, but an omitted flag triggers the real rolling computation. The threshold actually used is now also written to the output record as `thresholdMeanUsed` for auditability.

**Why this matters for future sessions:** Both bugs were found by reading the *documented* intent (research report, CLI help text) against the *actual* code and noticing they didn't match — a pattern worth repeating when reviewing this repo's "truth layer" logic, since the docs are often more aspirational than the implementation. If `reports/metrics.json` accuracy numbers ever look suspiciously high, check first whether `Unclassified` pairs are being counted as matches again (e.g. a future PR reintroducing plain equality) before assuming the PSI model itself improved.
