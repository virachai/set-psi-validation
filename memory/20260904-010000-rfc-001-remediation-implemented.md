**What shipped:** RFC-001 (`docs/02_rfc/001-rfc-psi-validation-remediation-v01.md`), all 11 issues, in 4 phases ordered by data dependency (capture → validation record/metrics shape → derived metrics → independent regime/timestamp fixes):

- **Phase 1** (`capture_market.py`, `providers.py`): atomic writes (temp file + `Path.replace`); `extract_market_prices()`/`_fetch_live_prices()` now raise `RuntimeError` on any missing/zero OHLC field instead of defaulting to 0.0; `handle_noon()`/`handle_atc()` raise instead of backfilling a missing ATO with the noon/ATC price; new `_assert_market_closed()` gate blocks `_capture_atc()` before 16:30 ICT; Finnhub/Yahoo quotes gained `fetched_at`/`source_granularity` metadata, with a WARN log when Yahoo's daily bar is used as if it were an ATO/ATC auction print.
- **Phase 2** (`validation_engine.py`): introduced a `"pending"` status — when `_resolve_market_outcome()` can't resolve any outcome for a session, `run_daily_validation()` now writes a record with `actualRegime`/`isCorrect`/`deviationScore` as `None` and `status: "pending"`, instead of silently skipping it; `update_aggregate_metrics()` excludes pending records and now dedupes by trading date (`groupby("date")`) before computing `rolling_7d`/`rolling_30d`, so a date with am+pm+full_day sessions contributes one row instead of three.
- **Phase 3** (`validation_engine.py`): added Precision and F1 per regime, derived from the existing confusion-matrix crosstab (`_compute_precision_and_f1`) — free, since the raw data was already computed for the (mislabeled) `hit_rates`/recall dict. Deliberately did NOT implement Calibration — no probability/confidence field exists anywhere in the prediction schema, so that would be new data collection, not a bugfix; docs-corrected `README.md` instead of building it.
- **Phase 4** (`regime_rules.py`, `predictions_loader.py`): Crisis threshold changed from `volatility_index >= threshold_mean * 2` to strictly `>`, matching the documented rule; `validate_timestamp()` now rejects naive (offset-less) timestamps and, when given an `expected_date`, rejects a timestamp whose ICT calendar date doesn't match it — both previously silent/unvalidated.

**Process note — plan mode + rule conflict:** This was done via a full Explore → Plan → ExitPlanMode cycle (3 parallel Explore agents mapped all 11 issues to exact file:line locations before a Plan agent designed the phased implementation). The repo's own `.claude/rules/005-outcome-first-v01.md` states a "Never-Implement mandate" forbidding agents from writing functional code. Before implementing, the user was asked explicitly whether to honor that rule (producing diffs only) or override it for this task; the user said to override it because they had explicitly directed this bugfix. This is a one-off authorization for this task, not a standing exception — the rule should still be surfaced/asked about the next time a request implies writing functional code in this repo.

**Why this matters for future sessions:** All 4 phases landed together in one pass (user's choice, not phased rollout) and all 148 tests pass with `ruff check` clean. Several existing tests encoded the OLD silently-fabricating behavior (`test_open_price_zero`, `test_atc_fallback_no_ato`, `TestHandleNoon.test_fallback_no_ato`) and had to be inverted to `pytest.raises(RuntimeError)` — if similar RFC-driven fail-closed work comes up again, expect to find and rewrite tests that were pinning the bug, not just adding new ones. `update_aggregate_metrics()` was at the Ruff complexity ceiling (C901/PLR0912/PLR0915) before these changes; two helpers were extracted (`_load_completed_validation_records`, `_compute_precision_and_f1`) to stay under the limit — any further additions to that function should extract another helper rather than growing it further.
